Limitations, and what I'd do next

  • Leaving isn't always losing interest. Some people leave because they've decided to buy, or join late from a replay link. Next: join each attendee's leave minute to whether they bought, so the drop is split into "lost" and "done".
  • Correlation, not cause. The drop lines up with a point in the session, but the console can't say what's said there. That's why the recommendation is an A/B test across alternate sessions, not a script change.
  • Minute resolution. Anyone present for part of a minute counts for that minute. Fine for 15-minute windows; too coarse for second-by-second edits.
  • "Qualified" is set at registration and doesn't change with what happens in the session. A better segment would add in-session signals: questions asked, polls answered.

How it's built

  1. Minute 0 is the scheduled start, not when the room opened. Comparing webinars only works on the same clock.
  2. Each person counts once per minute. Join/leave rows are merged per attendee first, so a dropped connection or a second device never inflates the count.
  3. Retention = people in the room at +N minutes ÷ peak. Peak is measured from minute 0, so early arrivals waiting in the lobby don't set it.
  4. Timestamps arrive in UTC and are converted to IST once, in the transform, never in the page.
